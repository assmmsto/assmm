# معرض الأعمال — Nova Work Showcase

معرض شخصي لعرض وبيع المنتجات الرقمية (أدوات، APIs، قوالب، تطبيقات).
**ملفات ثابتة 100%** — بلا سيرفر خاص وبلا build step — مع **قاعدة بيانات أونلاين مجانية** (Supabase) تعمل من طرف العميل مباشرة.
تعمل على GitHub Pages / Vercel / Netlify / أي استضافة تدعم Apache.

## المزايا
- كتالوج منتجات (بحث + فلاتر حسب النوع/السعر) — يُقرأ من القاعدة أو من `data/products.json` كاحتياط
- تفاصيل المنتج في مودال (ميزات + أوامر تثبيت + ترخيص)
- تحميل فوري للمنتجات المجانية
- شراء المنتجات المدفوعة: **محافظ فقط** — رقمية (USDT · BTC) أو محلية (شام كاش+ · فودافون كاش …). كل المحافظ المُفعّلة تُعرض للمشتري وهو يختار، ويضيفها الأدمن من تبويب «المحافظ». لا وسطاء ولا بطاقات ولا بنوك.
- **التسليم بنمط صريح**: `delivery.mode` أحد ستة — `file` · `repo` · `link` · `service` · `key` · `install`. لكل نمط واجهته وزرّه، والمجاني يُفتح والمدفوع يُقفل حتى تأكيد الدفع.
- **تتبّع الطلب** بحقل OTP متحوّل بالدوران (٦ محارف) — يستلم المشتري مفتاح الترخيص فور تأكيد الأدمن
- ترخيص بمفاتيح يديرها الأدمن (مخزون `licenseKeys` + مستهلك `usedKeys`)
- لوحة أدمن كاملة: CRUD منتجات، طلبات، محافظ، اقتراحات، إعدادات، مزامنة GitHub (نسخة احتياطية)
- **عين 👁 بجانب كل حقل** في نموذج المنتج: تُخفي/تُظهر ذلك الحقل للعميل لكل منتج على حدة (`hiddenFields`)
- **القاعدة الذهبية**: الحقل الفارغ لا يُرسم أصلاً عند العميل — لا عناوين ولا مساحات فارغة
- **حماية تلقائية للمدفوع**: أي منتج بسعر > 0 تُقفل حقول التسليم تلقائياً (رابط التسليم، دعوة GitHub، أوامر التثبيت) حتى لو نسي الأدمن
- **معاينة كعميل** 👁‍🗨 من جدول المنتجات أو من داخل المودال قبل الحفظ
- **المميّز ⭐**: حقل `featured` يُبرزه (شارة «مميّز» + إطار أساسي **برتقالي ذهبي** + ترتيبه أولاً)
- فلاتر سريعة: الكل · مجانية · مدفوعة · تطبيقات · أندرويد · CLI · APIs · قوالب
- PWA: تثبيت + عمل دون اتصال (`sw.js`) — بأيقونات PNG حقيقية و`maskable`
- ثيم داكن/فاتح (RTL أصيل) على نظام تصميم موحّد
- **تحديث تلقائي للتبويبات**: طلب جديد يظهر في اللوحة لحظة فتح تبويب «الطلبات» — بلا إعادة تحميل

## قواعد العرض الذكية (ما يراه العميل)
| القاعدة | التفاصيل |
|---|---|
| **الفارغ لا يظهر** | أي حقل لم يملأه الأدمن لا يُرسم في صفحة العميل: لا عنوان ولا صف فارغ |
| **المدفوع يُقفل نفسه** | `price > 0` ⇒ `downloadUrl` + `githubInviteUrl` + `installCommands` تُقفل تلقائياً وتظهر «يُسلَّم بعد تأكيد الدفع»؛ تُفتح في شاشة النجاح وصندوق التتبع بعد تأكيد الأدمن |
| **عين الأدمن** | `product.hiddenFields = ["field", …]` تخفي حقولاً بعينها لهذا المنتج (👁 بجانب كل حقل في النموذج) |
| **المجاني مفتوح** | `price = 0` ⇒ زر «تحميل» مباشر بلا قفل |
| **المميّز أولاً** | `featured: true` ⇒ شارة «مميّز» + إطار أساسي + ترتيب متقدّم في الشبكة (يُخفى إن أُغلقت عينه) |

## طرق الدفع للمنتج (بلا إدخال يدوي)
- عند إضافة/تحرير منتج: قائمة `<select multiple>` تُبنى **تلقائياً** من محافظ `wallets.json` المفعّلة + طرق `settings.json`.
- المحافظ المعلّمة `isDefault: true` في تبويب «المحافظ» تُحدَّد **تلقائياً** لكل منتج جديد.

## الخطوط
- **Cairo** للعربي · **IBM Plex Sans Arabic** · **Space Grotesk** للإنجليزي · **Oswald** للأرقام · **JetBrains Mono** للكود · **Material Symbols** للأيقونات.

## التشغيل المحلي
```bash
python -m http.server 8080     # أو:  npx serve .
```
ثم `http://localhost:8080`

> **الفتح المباشر بـ `file://` يعمل الآن** — البيانات تُضمَّن في الصفحة نفسها
> (`<script id="nova-data">`) وتُستخدم تلقائياً حين يفشل الجلب. لتجربة كاملة
> (Service Worker · PWA · تثبيت) شغّل خادماً محلياً.
>
> ⚠️ **بعد أي تعديل على `data/*.json` شغّل:** `python tools/embed-data.py`
> وإلا بقيت النسخة المضمّنة قديمة عند الفتح بلا خادم.

## 🗄️ قاعدة البيانات الأونلاين (Supabase)

المشروع يعمل بأحد وضعين تلقائياً عبر `db.js`:

| الوضع | متى | ماذا يحدث |
|---|---|---|
| **Supabase** | وُجد `supabaseUrl` + `supabaseKey` في `data/settings.json` | كل شيء أونلاين: المنتجات، الطلبات، الاقتراحات |
| **محلي** | غاب المفتاح أو فشل الاتصال | JSON + `localStorage` — لا يتوقف الموقع أبداً |

الخطأ **لا** يُظهر رسالة خطأ للزائر — يسقط للوضع المحلي بصمت ويستمر العمل.

## 🚀 النشر للإنتاج

### 1) ما يُرفع وما لا يُرفع
**يُرفع:** `index.html` · `admin.html` · `app.js` · `admin.js` · `db.js` · `styles.css` · `sw.js` · `manifest.json` · `assets/` · `data/` · `robots.txt` · `sitemap.xml` · `.htaccess`

**يُرفع لكنه محجوب عن الويب** (`.htaccess` يمنعه): `tests/` · `tools/` · `.workbuddy-ai/`

**لا يُرفع:** `test-*.py` · `supabase-schema.sql` · `*.md` · `demo-*.html` · `admin_stitch.html`

### 2) قائمة تحقق قبل الرفع
- [ ] **استبدل `https://example.com` بنطاقك** في `index.html` و `robots.txt` و `sitemap.xml`
- [ ] ضع مفاتيح Supabase في `data/settings.json` (أو من تبويب الإعدادات)
- [ ] ارفع `.htaccess` (Apache) — أو انقل قواعده لإعدادات Nginx
- [ ] **فعّل حماية `admin.html`** بكلمة مرور (القسم 9 في `.htaccess`) — راجع التحذير هناك
- [ ] تأكد أن HTTPS يعمل، ثم فعّل HSTS في `.htaccess`
- [ ] افتح الموقع وتأكد أن أيقونة التثبيت (PWA) تظهر

### 3) بعد أي تعديل على CSS/JS
ارفع الرقم في ثلاثة أماكن معاً (يضمن أن الزوار يرون النسخة الجديدة فوراً):
1. `?v=N` في `index.html` و `admin.html`
2. `CACHE_NAME` في `sw.js`

### 4) تجديد أصول الهوية
```bash
python tools/make-assets.py
```
ينتج الأيقونات (PNG + maskable) وصورة المشاركة `assets/og-image.png`.

## 🛡️ الأمان
- مفتاح Supabase **publishable** مصمّم ليكون عاماً — ظهوره في الكود طبيعي.
- الحماية الفعلية عبر **Row Level Security** (مضمّنة في `supabase-schema.sql`).
- بوابة الأدمن: كلمة مرور محلية مُجزّأة SHA-256 في `localStorage` — **أداة محلية، ليست مصادقة خادمية**.
- للإنتاج الجدّي: فعّل حماية `.htaccess` (Basic Auth) على `admin.html`، أو Supabase Auth.
- `data/settings.json` يُقرأ من المتصفح — لا تضع فيه أسراراً حقيقية (التوكن وكلمة المرور يبقيان في `localStorage` فقط).
